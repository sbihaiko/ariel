# Exit codes of the agent port

The registry of every `exit <n>` value the agent port answers. A number is assigned here before code uses it, and a number is never reused for another meaning. A reply always ends with one `exit` line; the word on the line before it names the reason.

`payload run --wait` reports the payload's own status on a `status <n>` line, then `exit 0`. A payload's status never appears on the `exit` line.

`payload run <name>` without `--wait` answers `pid <n>` then `exit 0` at once and runs the payload in the background, cut at its timeout. `payload logs <name>` shows what the payload printed, then `exit 0`; for a payload still running it waits until the payload exits. `payload list` marks a background payload that is still going as running.

A shell command (`pwd`, `cd`, a read-only command that takes a path: `ls`, `stat`, `file`, `cat`, `grep`, `find`, `cmp`, `hexdump`, `df`, `sha256sum`, or an inspection command: `echo`, `help`, `id`, `sync`, `sleep`, `sum`, `sfoinfo`, `ps`, `procstat`, `sysctl`, `authid`) writes its output and its error word to the connection and ends with `exit <n>`, where `n` is the command's own status: 0 for success, 1 for an error such as `relative_path` or `no_working_directory`. `grep` and `cmp` also exit 1 when nothing matches or the files differ. A connection has no working directory, so every path is absolute and `cd` always fails.

The inspection commands add these error words, all with exit 1: `missing_operand` (an operand is required), `bad_duration` (`sleep` takes whole seconds from 0 to 60), `not_a_pid` (`procstat` takes a decimal pid), `no_such_process` (no process has that pid), and `not_sfo` (the file is not a PARAM.SFO). On the host build, `authid` answers `not available on this platform`, because it reads the console's kernel credentials. A `sysctl` write (`sysctl name=value`) or an `authid` with an operand is outside the read-only set, so it is gated like any other unlisted command.

The file commands `mkdir`, `rmdir`, `touch` and `rm` take one absolute path. Each one answers `approval_required` (75) with a challenge first, and runs only after the owner signs it. The challenge binds the path and the entry's identity (kind, device and inode); the approval is single-use. Any other command outside the read-only set is gated the same way and then does nothing, answering `unknown_command`. A write outside `/data`, `/user` and `/mnt/usb*` answers `protected` (87) without asking.

An executable is run by its absolute path, or by a bare name the `PATH` holds. Its first answer is `approval_required` (75) with a challenge. The challenge binds the resolved path, the file's SHA-256, its identity (kind, device and inode) and its arguments, one option each; the approval is single-use. After a grant the same command runs the bytes that were hashed, prints the payload's output, and answers `status <n>` with its own status, then `exit 0`. A file changed or replaced after approval answers `approval_stale` (78) and does not run. A run with other arguments than were signed answers `approval_stale` too, and a granted approval it finds is spent by that answer. A run never follows a symbolic link: a path, or a `PATH` entry, that is one answers `symbolic_link` with exit 1 and no challenge. A file over 64 MiB answers `too_large` with exit 1 and no challenge. A run with more than eight arguments, an argument over 64 characters, or an argument with a character outside letters, digits, `.`, `_` and `-` answers `unknown_command` with exit 1 and no challenge. The audit log records `run.request`, `grant`, `run.start` before the payload starts, and `run.status` after it returns, whose fifth column is `status-<n>`; a payload the loader cannot start is `run.failed`.

`kill <pid> <SIGNAL>` is gated like a payload commit: it answers `approval_required` with exit 75 until the owner signs its challenge, which binds the pid, the signal and the process's start identity. After a grant, the same command runs once and answers `killed <pid> <SIGNAL>` with exit 0. Its error words are `bad_signal` (the signal is not TERM, KILL, INT or HUP), `no_such_process` and `kill_failed`, all exit 1; a pid that is not a decimal number answers `unknown_command`, and a kill with another argument count is an unlisted command, gated like any other. The audit log records `kill.request`, `kill.done`, `kill.stale`, `kill.failed` and `kill.protected`, like the file commands. Exit 87 (`protected`) covers a kill of a critical process and of Ariel's own process; those are refused whether or not an approval exists. A process that was restarted under the same pid answers `approval_stale` with exit 78, and its approval is spent.

`chmod MODE PATH`, `chown ID PATH` and `chgrp ID PATH` are gated the same way. The mode is octal up to `07777`; the owner and group are decimal ids below 4294967295. The challenge also binds the requested mode, owner or group, so a different one answers `approval_stale`. A bad operand answers `bad_mode`, `bad_owner` or `bad_group` with exit 1 before anything is asked; a missing one answers `missing_operand`. A symbolic link to a protected object answers `protected` (87), and the link is never followed to change its target.

The transfers `cp`, `mv` and `ln` take a source and a destination, both absolute. The source must be a regular file (a directory answers `is_a_directory`, a symbolic link `symbolic_link`, a file that is not regular `not_a_file`), and the destination must not exist (`exists`, exit 1); nothing is ever replaced. Each one answers 75 with a challenge that binds both paths, sha256 `none`, and the source's identity, and runs only after the owner signs it. `cp` copies the bytes and leaves the source; `mv` moves the name and removes the source; `ln` makes a hard link. A source that changed after the signature answers `approval_stale` (78), and nothing moves. Every path involved is checked for protection: the source and destination, the directories above them, and the target of a symbolic link, so a link to the token answers `protected` (87) even when approved. A pair of paths whose audit subject would be longer than 180 characters answers `bad_path` before anything is asked.

`tar -t ARCHIVE` lists a ustar archive at once: one member name per line, then `exit 0`. `tar -x ARCHIVE DEST` answers `approval_required` (75) with a challenge that binds the archive's sha256, its identity (kind, device and inode) and the destination; it extracts only after the owner signs, and an archive or destination that changed since then answers `approval_stale` (78). A member whose name is absolute or climbs out of the destination (`../`) answers `escaping_member` (1), and a link member that leaves the destination answers the same. A member that is not a plain name, a directory, a file or a link answers `bad_member` (1), and a link inside the destination is refused as `bad_member` too, since this slice does not extract links. A file that is not a ustar archive answers `not_a_tar` (1). Every member is checked before the first one is written, so a refused member leaves nothing behind. A member whose path already exists under the destination answers `exists` (1). The archive or destination being a protected object answers `protected` (87) even with an approval.

The system commands `mount -t <fstype> <from> <dir>`, `umount <dir>`, `chroot <dir>` and `mknod <path> b|c <major> <minor>` are gated like the file commands. Their challenge binds the target, the options (the file system type and source for `mount`; the type, major and minor for `mknod`) and the target's identity. A wrong argument count or shape answers `bad_argument` (1) without asking. A target, or a symbolic link to one, that is a protected object answers `protected` (87) even with an approval. On the host build, which cannot run them, a signed command answers `not available on this platform` and `exit 1`; the attempt is audited as `<command>.unavailable`.

`env NAME`, `export NAME=VALUE` and `exec <path> [args]` are gated the same way. Each one answers `approval_required` (75) until the owner signs its challenge, and each signed action names one thing: `env` the variable, `export` the variable and the hash of its value, and `exec` the program, the hash of its bytes, and its arguments (their count and a hash). A grant runs the command once. `env` prints `NAME=value` when the variable is set, then `exit 0`; `export` answers `exported NAME` with exit 0; `exec` runs the program, prints its output, then `status <n>` and `exit 0`, where `<n>` is the program's own status. A changed value, argument list or program answers `approval_stale` with exit 78 and runs nothing. The words `bad_name` (exit 1) refuse a name that is not a letter or `_` followed by letters, digits or `_`, of at most 32 characters, and `export_failed` and `value_too_long` (exit 1) refuse a variable that cannot be set or shown. `exec` answers `relative_path`, `bad_path`, `no_such_file`, `not_a_file` and `symbolic_link` as the file commands do, and `too_large` (exit 1) for a program over 64 MiB. A program outside the root answers `protected` (87) without asking, as does a protected object such as the token. The audit log records `env.request`, `env.done`, `env.failed`, `env.denied` and `env.refused`; the same set for `export` and `exec`, with `export.stale`, `exec.stale`, `exec.failed` and `exec.protected` as well; and each refusal of a name or a path.

`unzip -l ARCHIVE` lists the archive's members as `size name` lines, then `exit 0`, at once and without asking. `unzip ARCHIVE DEST` answers 75 with a challenge that binds the archive's sha256 and the destination, and extracts only after the owner signs it. The archive is read whole, up to 16 MiB, and only its stored members are accepted: an archive that is not a zip, is larger than 16 MiB, has a deflated, encrypted, zip64 or multi-disk member, a duplicate name, or a control character in a name answers `bad_archive` (exit 1). The destination must be an existing directory; an existing member answers `exists`. A member whose name is absolute, holds `..`, a backslash or an empty part refuses the whole archive with `unsafe_member` (exit 1) before anything is asked or written. An archive changed after the signature answers `approval_stale` (78). The archive and destination are both checked for protection, through links too, and answer `protected` (87) even when approved. The audit log records `unzip.list` for a listing, and `unzip.request`, `unzip.done` and `unzip.refused` for an extraction. The canonical encoder refuses `.` in a path segment, so an archive or destination whose name holds a dot answers `bad_path`.

The built-ins `launch`, `pkg_install`, `hbldr`, `hbdbg`, `suspend`, `notify` and `reptyr` are gated the same way: each answers `approval_required` (75) with a challenge first, and runs once through its own process after the owner signs it. The challenge binds the command and its target (the title ID for `launch`, the path for `pkg_install`, `hbldr` and `hbdbg`, the word for `notify`, `suspend` itself, the pid for `reptyr`), each argument after the target as text (options `arg1` to `arg5`, in order), and for a file the entry's kind, device and inode; `reptyr` binds the process start identity instead, like `kill`. A changed argument, entry or start answers `approval_stale` (78), and the approval is spent. A missing operand answers `missing_operand`; a `notify` word that is not a single target-valid word, a `reptyr` pid that is not decimal, an argument that is not a word of letters, digits, `.`, `_` and `-` up to 64 bytes, or a sixth argument after the target answers `bad_argument` (exit 1) before anything is asked. A relative path, a path that is not a regular file, and a protected path are refused with their usual words before anything is asked. On the host build a granted built-in answers `not available on this platform`, because it needs the console. The audit log records `<command>.request`, `<command>.done`, `<command>.stale`, `<command>.denied`, `<command>.refused` and `<command>.protected`.

`reboot` takes no argument and is gated: it answers `approval_required` (75) with a challenge that binds the command, the target `console` and the sha256 of the autoload list the restart will run. After a grant, the same command answers `rebooting` with exit 0 and the restart follows; the audit log records `reboot.done` before it. A reboot the owner denied answers `approval_denied` (77), and a changed autoload list answers `approval_stale` (78); neither restarts. A restart that cannot start is audited as `reboot.failed`. The audit log records `reboot.request`, `reboot.done`, `reboot.failed`, `reboot.stale` and `reboot.denied`. On the host build, the restart runs the autoload entries as a boot does; a restart without that, as after a crash, runs none of them.

## Assigned

| Exit | Word | Meaning | What the agent does |
|---|---|---|---|
| 0 | | Success | |
| 1 | `unknown_command`, `bad_name`, `unknown_payload`, `ariel_pinned`, `already_in_autoload`, `not_in_autoload`, `autoload_full`, `autoload_failed`, `grant_failed`, `not_executable`, `already_running`, `too_many_runs`, `no_log`, `log_failed`, `spawn_failed`, `no_previous_version`, `rollback_failed`, `bad_argument`, `relative_path`, `bad_path`, `exists`, `no_such_file`, `not_a_directory`, `is_a_directory`, `not_a_file`, `symbolic_link`, `operation_failed`, `bad_mode`, `bad_owner`, `bad_group`, `missing_operand`, `too_large`, `export_failed`, `value_too_long`, `unsafe_member`, `bad_archive`, `escaping_member`, `bad_member`, `not_a_tar`, others | Any other error | Read the word; do not retry as is |
| 70 | | Missing or wrong token; the connection is closed | Fix the token |
| 75 | `approval_required` | The action waits for the owner's signature; the reply carries the challenge | Have the owner sign, send `approval grant`, then repeat the command |
| 76 | `approval_busy` | Too many pending approvals, or a notification shown less than 10 s ago | Wait and push again |
| 77 | `approval_denied` | The owner refused. Only the host build's virtual source can refuse; the PS5 has no refusal, an unsigned approval expires | Do not retry |
| 78 | `approval_stale` | The approved target changed, or the approval is gone. A file command, a transfer or a system command answers it when the entry at its source or path is no longer the one the owner signed (replaced, or removed and created again), or when a chmod, chown or chgrp asks for another mode, owner or group than the one signed, or when an unzip archive's hash or identity changed after the signature; the approval is spent | Request a new challenge |
| 79 | `signature_invalid` | The signature does not verify against the pinned key | Do not retry with the same signature |
| 80 | `staging_full` | Staging is over its count or size limit | Wait for the TTL or commit pending objects |
| 81 | `upload_mismatch` | The upload ended early, ran past its size, or its hash differs | Push again |
| 82 | `busy` | Four connections are already served | Retry shortly |
| 83 | `signature_malformed` | The signature, console or action hash is not well-formed hex or is too long | Fix the `approval grant` line |
| 84 | `approval_replayed` | The signature's nonce was already consumed | Push again for a fresh challenge |
| 85 | `signature_action_mismatch` | The signer signed a different action than this approval | Sign this approval's challenge |
| 86 | `signature_console_mismatch` | The signer signed for another console | Sign with this console's identity |
| 87 | `protected` | The command reads or writes one of Ariel's protected objects: the token, the approval state, the consumed nonces, the audit log, the state file or the state directory itself, directly, through a symbolic link or through a hard link. A file or system command that writes outside `/data`, `/user` and `/mnt/usb*` is also refused here. Refused even with an approval | Do not retry; these files are Ariel's own |
| 88 | `approval_expired` | The approval passed its expiry before it was granted or used | Push again |

Free from 89. The `status <n>` line is outside this registry.
